- minimal diffs. do not make unrelated/irrelevant changes unless explicitly told to do so

- use long unambiguous names and clear structure to convey meaning
- freely use empty lines to emphasize structure
- minimal use of comments (only as a last resort)

- write simple and specific code
- do not write very general future-proofed (bikeshedded) code

- flat structure > deeply nested hierarchies
- a few files with many lines > big sprawl
- few large inlined functions > many helper functions that are only called in one place
